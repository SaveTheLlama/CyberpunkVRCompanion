# Contributing and Community Feedback

Cyberpunk VR Companion is intended to improve through real user feedback.

You do not need to be a developer to contribute.

## Report a bug

Use the **Bug Report** Issue form when something is reproducibly broken.

Before filing:

1. Update to the latest Companion release.
2. Run **Health**.
3. Create a **Diagnostic Pack** when useful.
4. Search existing Issues for the same problem.
5. Include exact reproduction steps.

Do not post saves, credentials, private screenshots, or unrelated personal files.

## Request a feature

Use the **Feature Request** Issue form for a concrete improvement that could reasonably become development work.

Good feature requests explain:

- what should change;
- what problem it solves;
- what the expected workflow would be;
- when the user would actually use it.

Feature requests may remain open while they are evaluated, grouped with related ideas, planned for a future milestone, or declined if they conflict with the project's safety/reliability goals.

## Use Discussions for ideas and questions

When GitHub Discussions is enabled, use it for:

- open-ended ideas;
- brainstorming;
- usage questions;
- community profile/settings discussion;
- experimental concepts that are not yet defined well enough to become a Feature Request.

A useful rule:

**Discussion = let's explore this.**

**Feature Request = this is a concrete change we may build.**

**Bug Report = something that should work is not working.**

## Testing experimental builds

Some future changes may be offered to willing users as experimental/test builds before they become stable releases.

Experimental builds should never be treated as replacements for the current stable release until validated.

## Pull requests / source contributions

Source-code contribution rules will be defined separately if/when the application source is published under an explicit license.

Until then, the public repository may primarily serve documentation, releases, support, feedback, and community discussion.
